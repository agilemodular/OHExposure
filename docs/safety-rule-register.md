# Safety-rule register

Each rule from the product brief, how it is enforced, and the evidence. "DB" = enforced in PostgreSQL (trigger, constraint or RLS) and therefore holds even if application code is wrong. Test names refer to `test/*.test.ts`.

| # | Rule | Enforcement | Evidence |
|---|---|---|---|
| S1 | No automatic "safe" or "compliant" verdict from a low reading | No such field exists. Engine output is limited to data-quality and benchmark-comparison states with a fixed disclaimer. "Below benchmark" is rendered in a neutral colour, never green. Conclusions are written and approved by people. | calc: *never yields a safe/compliant verdict field* |
| S2 | Missing data stays visible | Missing duration, flow, result, exposure period or coverage produces an *incomplete* flag and no number. Dashboard "missing evidence" rules list gaps with links. | calc: *missing flow or duration…*, *produces no TWA when unsampled…*, *requires an exposure period* |
| S3 | Non-detects never become zero | Carried as [0, LOD] intervals; no point estimate; roll-up becomes *indeterminate* when the interval spans the benchmark. | calc: *never replaces a non-detect with zero*, *non-detect without any limit is incomplete* |
| S4 | Failed QC checks cannot silently become valid evidence | A failed check excludes the sample until a practitioner/reviewer records a disposition with ≥ 20-character justification. Accepted failures remain flagged in the calculation and report. A new QC result after calculation blocks approval (inputs hash changes). | calc: *excludes a sample with an unresolved failed QC check*; workflow: *blocks approval if evidence changes…* |
| S5 | Screening instruments not represented as universally suitable | `screening_only` instruments and methods not designated for formal assessment produce *indicative* results, excluded from formal benchmark comparison and labelled in UI and reports. | calc: *labels screening-only instruments*, *treats screening-only evidence as not formally comparable* |
| S6 | A benchmark comparison is not a complete compliance conclusion | Disclaimer embedded in every calculation output and report; professional interpretation, conclusion and limitations are mandatory for submission. | calc: disclaimer assertion; workflow: *…interpretation* rejection |
| S7 | Static results not compared with personal benchmarks | Static samples are excluded from TWA grouping and listed separately as contextual evidence. | calc: *ignores static samples*, *treats static-only evidence as not comparable* |
| S8 | No extrapolation of partial-shift measurements without a documented, reviewable method | Default assumption is *none* → no TWA. Either assumption requires a justification that is stored, displayed and printed. | calc: coverage and justification tests |
| S9 | Software does not authorise hazardous work or replace emergency procedures | No permit, authorisation or emergency function exists. The WorkAssura contract is informational and states it never authorises work. | Scope document; contract text |
| S10 | Approval records reviewer identity, time, scope and limitations | DB check constraint requires reviewer, time, scope, limitations, snapshot and hash for status *approved*; confirmation checkbox required. | workflow: *calculates, reviews and approves…* |
| S11 | Approver independent of author | Approver cannot be the revision creator or submitter. | workflow: practitioner approval rejected |
| S12 | Material change after approval creates a new revision requiring review | DB trigger blocks any update to an approved revision other than to *superseded/withdrawn*; edits require `newRevision` → draft → review. | workflow: *keeps approved revisions immutable at the database level*, *flags staleness…* |
| S13 | Historical benchmark reproducibility | Benchmark version frozen in the approved snapshot; newer/withdrawn versions only raise a notice. | workflow: staleness test; spec §5 |
| S14 | Never invent missing limits | No real limits shipped; unverified tenant entries unusable; verification by a second person; synthetic demo value labelled everywhere. | workflow: *does not compare with an unverified benchmark* (calc) |
| S15 | Separate states, no single traffic light | Three-segment evidence strip in UI; separate columns in reports and dashboards. | UI review (screenshots) |
| S16 | Installation alone is not verified control | Effective outcome for an engineering control requires a satisfactory performance test / thorough examination / commissioning dated after implementation, or an approved post-control assessment. Actions flagged as needing reassessment require an approved revision dated after implementation. | workflow: *requires verification evidence before closing a control action* |
| S17 | Five separate action milestones | State machine assigned → implemented → evidence submitted → effectiveness reviewed → verified closed; *not/partially effective* reopens; every transition append-only. | workflow: event sequence assertion |
| S18 | Before/after comparisons show non-comparability | Comparison view lists differences in method, duration, tasks, operating conditions, control status and sample types, with a warning. | calc: *surfaces differences…* |
| S19 | Defects raise tracked actions | Defective/failed inspection sets control *defective*, raises an action and flags the linked group for review. | workflow: *a defective inspection raises a tracked action* |
| S20 | Group membership changes do not rewrite history | `group_id_at_sampling` frozen at capture; memberships end-dated, never edited. | workflow: *preserves historical group association* |
| S21 | Field records never silently overwritten | Optimistic version check online; offline stale edits stored as conflicts with both copies; locked once dispatched. | workflow: offline sync test; browser test (test-evidence) |
| S22 | AI cannot invent, approve or decide | No AI provider configured; the suggestion interface only stores labelled pending text and can only write into a *draft* interpretation after human acceptance. | Code review: `src/services/ai.ts` |
| S23 | Demonstration data labelled and isolated | Demo is its own tenant (`is_demo`), banner on every page and report; synthetic reference rows flagged. | Screenshots; seed script |
| S24 | Voided samples are never evidence | Engine excludes `voided` samples; voiding after calculation changes the inputs hash and blocks approval. | review-regressions: *C2 void samples* |
| S25 | Evidence from one client cannot enter another client's assessment | Service checks on group/plan/assessment client; DB trigger on `sampling_events`. | review-regressions: *C1* |
| S26 | Excluded or indicative results at or above the benchmark cannot be outweighed silently | Roll-up becomes *indeterminate* with the sample codes named. | review-regressions: *M3*; calc test |
| S27 | Unsampled time cannot be dropped by under-stating the exposure period | Exposure period shorter than the register duration is *incomplete*. | review-regressions: *H4* |
| S28 | "Exposure adequately controlled" only when every formal result is below a verified benchmark | Submission and approval guard. | service rule (`checkConclusion`) |
| S29 | Defect actions cannot be cancelled by their creator or without reviewer rights; a defective control cannot return to service while defect actions are open | Service rules. | review-regressions: *H5* |
| S30 | Results without instrument or valid calibration evidence are not formal evidence | Engine labels them indicative; they cannot support a below-benchmark roll-up and can make it indeterminate. | review-regressions: *H4* |
| S31 | Indicative or excluded results in an unconvertible unit cannot be ignored | Roll-up becomes indeterminate and names them. | review-regressions: *H5* |
| S32 | Short-term results need a continuous ~15-minute window | STEL refuses samples whose elapsed window exceeds 16 minutes. | review-regressions: *M3* |
| S33 | Evidence behind assessments cannot be voided casually | Voiding a dispatched/received/analysed sample needs practitioner rights and a full reason; approved assessments show a staleness notice. | review-regressions: *M2* |
